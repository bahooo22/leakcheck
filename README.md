# leakcheck — единая мера текстовых утечек

Инструмент вне репозиториев: один набор правил для всех проектов про иероглифы,
склейку кириллицы с латиницей, склейку через точку и вкрапления, похожие на
секрет. Знания о конкретном проекте подключаются модулем через `--ext ФАЙЛ`.

## Зачем он появился

Мерка жила в трёх расходящихся копиях, и канон по факту был самой слабой из
них: глобальные ритуалы (`russian-commit-body-ritual`,
`qoder-agent-report-archive`) звали копию от 09.10, где склейка искалась по
соседним символам. Такая версия пропускала вставленную в слово цифру
(`задач2Search`), не считала склейкой точку (`слово.имя`) и не знала мерки
прозы — ровно те два дефекта, из-за которых опечатка проскочила в тело коммита
дважды. Сильная копия (репозиторий локализации Qoder) уметь это умела, но не
переносилась: импортировала модуль проекта и знала его словари.

Отсюда форма: правила — здесь, проектные данные — в дополнениях.

## Запуск

```
python -X utf8 leakcheck.py [ФАЙЛ…]                 # общая мерка по файлам
python -X utf8 leakcheck.py --ext ФАЙЛ --mode ИМЯ   # режим проекта
python -X utf8 leakcheck.py --version               # версия ядра
```

Коды выхода: **0** — чисто, **1** — есть находки, **2** — вход пуст или не
читается, результат неинформативен. Единица — сигнал, а не счётчик находок; ноль
по пустому файлу не является проверкой, поэтому для пустого и для нечитаемого
входа (опечатка в имени файла) свой код — иначе `traceback` с кодом 1 выглядит
как удачная ловля дефекта.

Флаги: `--prose-num` (печатать и оборот «число + слово» — только для вычитки,
легальных таких мест сотни: на собственном `README.md` флаг даёт 4 находки вида
«24 проверки» и «от 16 символов»), `--latin` (список латинских токенов вне
код-спанов на ручной смотр), `--no-secret` (выключить поиск похожих на секрет
вкраплений), `--prose ФАЙЛ…` (то же, что позиционные файлы — для совместимости
с прежними командами ритуалов).

Флаг обязан стоять ДО `--prose`: у `argparse` список файлов `--prose` жадный, и
`--prose --prose-num ФАЙЛ` разбирается как «флагу нужен аргумент» — код 2 вместо
прогона (проверено 14.10).

## Что мерит ядро

| класс | правило | почему так |
|---|---|---|
| иероглифы | `CJK` (слоги, идеограммы, расширения, fullWidth) | в русской прозе и исходниках им не место |
| смешение | `MIXED_RUN` + `mixed()`: один запуск букв и цифр, в котором есть и кириллица, и латиница | поиск по соседним символам пропускал цифру внутри слова |
| склейка через точку | `DOT_GLUE` | точка — не разделитель: `слово.имя` это та же склейка |
| секрет | `SECRET`: `token = …`, `api_key: …` и прочее со значением от 16 символов | распечатанный конфиг или токен в отчёте агента |

Содержимое обратных кавычек и экраны литералов (`\t`, `\n`) вырезаются до
счёта: `documentElement.lang` — данные, а не русское предложение, а буква
экрана склеивается со следующим словом. Дефис остаётся разделителем, поэтому
«Git-репозиторий» и «HTML-артефакт» не находки: легальных дефисных склеек в
русских словарях десятки, и приклейкой их считать нельзя.

## Форма проектного дополнения

Модуль подключается флагом `--ext ФАЙЛ` и может объявить любое из:

| имя | что даёт |
|---|---|
| `EXTRA` | список `(заголовок, regex)` — новые классы находок поверх четырёх базовых |
| `DATA` | dict `keep_tokens` / `brand_values` / `brand_titles` — легальные совпадения с английским |
| `MODES` | dict `{"имя": вызываемый(core, args)}` — целый режим проекта |
| `ADD_ARGUMENTS` | список `(флаги, kwargs argparse)` — проектные флаги режима |
| `VERIFY_TARGETS` | пути, которые обязаны существовать — гейт «дополнение подключено к живому проекту» |

Ядро не знает ни одного бренда: `verbatim_ok("Finder")` без `DATA` даёт
`False`. Так проектные списки не могут молча расширить мерку для всех.

Почему бренды — значениями целиком, а не токенами: в токен-лист уехали бы
`file` и `icons`, и реальный недосмотр вида «File» вместо «Файл» перестал бы
ловиться.

## Гейты

`python -X utf8 test_core.py` — 24 проверки: ловля в обоих порядках, случай
пропустившей точки, цифра внутри слова, данные в кавычках, дефис, иероглифы,
секрет и его отключение, пустой вход и вход, которого нет на диске, единица
вместо счётчика, контракт дополнения (`EXTRA`, `ADD_ARGUMENTS`,
`VERIFY_TARGETS`, неизвестный режим), базовые правила `verbatim_ok`, счётные
формы, обход словаря.

Последняя проверка — «мера проходит саму себя»: читается **файл ядра**, а не
обёртка проекта. Примеры дефектов в docstring поэтому стоят в обратных
кавычках. Исходники тестов под эту мерку не кладут: они хранят дефекты как
образцы, и счётчик посчитал бы их находками.

## Потребители

- `Qoder_i18n/tools/scan_leaks.py` — тонкая обёртка: реэкспорт имён для семи
  инструментов проекта плюс режим `dict` (словарь переводов и покрытие).
- `_work_with_llm\glm\scripts\scan_leaks.py` — был слабой копией меры (3 142
  байта, без точки-склейки, прозы и разметки) и «канонам по факту» для ритуалов
  во всех проектах. С 14.10 это указатель на ядро: ищет каталог из
  `LEAKCHECK_HOME`, затем `/opt/leakcheck`, затем абсолютный путь репозитория, и
  при отсутствии ядра падает с перечислением всех проверенных путей. Прежний снимок
  лежит в `glm\scripts\_superseded\scan_leaks_weak_2026-10-09.py` — для прогона
  он не годится ровно из-за того, из-за чего его и снимали.
- Контейнер `gdlab` получает ядро тем же механизмом, что и остальные мерки:
  `glm\scripts\gdlab-sync.sh` раскладывает `leakcheck.py` в `/opt/leakcheck`,
  печатает `--version` и прогоняет три контрольных входа двумя путями — ядро
  напрямую и указатель (ждём 0 / 1 / 2, посаженная находка — склейка через
  точку, которую слабая копия пропускала). Монтирование не нужно: у контейнера
  примонтировано только дерево проекта в `/work`, а пересоздание ради флага `-v`
  стоило бы перезапуска всего стенда. Скрипт запускает владелец машины, потому
  что `docker exec` агенту запрещён.
